# v3.13 Voice that fails says so: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hold to talk never fails silently. Every failure either recovers or says plainly what happened:
- a transcript can't crash;
- Lerni never sends silent audio;
- the microphone isn't left on;
- a long recording isn't cut short;
- a broken microphone hands over to Type.

**Architecture:**
- **`adapters/mac_speech.py`:**
  - **Transcripts:** `transcribe` reads whisper's output as bytes and decodes it with `errors="replace"`. A transcript that ends mid-letter (an accented character cut short) becomes a "�" instead of an uncaught `UnicodeDecodeError` (seen in production 2026-10-13).
  - **Silent audio:** `speak` raises `SpeechUnavailable` when `say` writes under 1 KB. An empty file is 28 bytes; "Hi" is 35 KB. So a sentence is shown as text instead of being sent as silence.
  - **A startup check:** `mac_speech_from_env()` returns `(speech, why_off)`. It also checks that `say` really makes sound, with one short phrase. Startup prints `Voice (hold to talk): off (<why>)` with the reason:
    - the tools are missing;
    - `say` makes no sound (started over SSH or in tmux).
- **`web/talk.js`:**
  - **The microphone is released when you let go too early.** If you let go before Safari's microphone prompt is answered, the stream it then grants is stopped at once. Today it stays open, and Safari stays in quiet call-volume playback.
  - **Long recordings send.** At 29.5 seconds the clip sends itself, as if you'd let go. Today everything after 30 seconds is dropped.
  - **A broken microphone switches to Type.** If the microphone is refused or missing, the dock switches to Type, and the question box's placeholder says "The microphone isn't working here, so type instead."
- **`ProcessType`: no change.** A spike on 2026-10-20 timed whisper on a 6-second clip three times in a Terminal shell and three times under a one-off LaunchAgent: about 0.75 s in both.

**Tech Stack:** Python 3.11+, vanilla JS (no build), pytest with fake runners.

**Spec:** [spec 05](specs/05-voice.md); the student PRD's voice criteria.

## Global Constraints

- **Audio stays on the home server**, in temp files deleted at once (unchanged).
- **Tests:** two regression tests in `tests/student/test_voice.py`, one per server bug: decoding, and silent audio plus the startup check.
  - There is no JS test harness. The JS changes are checked by reading them and by hand on the iPad (an admin step).
- **No fine print on screen:** the one new line is the placeholder.

## Review Focus

1. **Auto-send at 30 s and letting go at 30 s at once:** one clip is sent, not two.
2. **The startup check:** it runs one `say` (about a second), never at each answer.
3. **A `say` that hangs at startup:** the 30-second timeout applies, and Voice is turned off with that reason.
4. **The Type switch:** it's saved like a tap on Type, so it stays on that device until the student taps Talk.
5. **Whisper output that is all "�":** it's treated as heard nothing.
