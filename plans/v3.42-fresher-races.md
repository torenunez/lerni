# v3.42: fresher races

**Goal:** Race questions stop feeling like the same few questions again. In short:
- Each goal remembers its own ideas for a month.
- Goals the student does well on stop coming back every day.
- Every question gets a format and a twist the server rolled, so no two sets are written from the same prompt.

**Why (the admin, 2026-11-10):** the same few topics and nearly the same questions kept coming back. Production's results log for the last two weeks, read on the home server and never copied here, showed four causes:
- **Goals stuck in a loop.**
  - A goal gets 1–2 questions a race, so one miss counts as "half or fewer right", and that sends it back to box 0, due tomorrow (`concepts.py:154`).
  - At level 5, the wrong choices are near misses on purpose, so about one miss a race is expected.
  - So the student's strongest goals stayed due every day, and every set took them first.
- **A short memory.** Claude is told only the last 40 idea labels across all goals (`KEEP_RECENT`). At the current pace that's 2 to 3 days, so ideas came back after about 3 days.
- **Car comparisons.** About 1 question in 5 on a goal about numbers or moving had to compare two cars by a number. On goals raced daily, the same comparisons came back.
- **One prompt.** Only 4 angles are named, and nothing in the prompt changes from one set to the next. Temperature can't be raised instead: current Claude models reject it, and Claude Code doesn't expose it.

The admin approved ten suggestions plus "the dice" (2026-11-10). This version is the first five; v3.43 (every interest, new bridges) follows it straight away.

## What changes

- **The goal schedule (`concepts.py`, `ConceptStore.raced`):** half or fewer right in a race moves a goal **back one box** (box 2 → 1, box 1 → 0) instead of always to box 0.
  - All right on a due goal still moves it up a box.
  - Partly right still keeps it where it is.
  - A level-5 goal that's mostly right now settles at a 3- to 7-day gap instead of daily.
- **Each goal's own memory (`concepts.py`, new `asked_by_goal`):**
  - **What's kept:** each goal's idea labels asked in the last **30 days** (`IDEA_DAYS`), newest first, at most 30 a goal. Labels only, as today (rule 6).
  - **What Claude is told:** each picked goal's line carries its own list: `- Fractions (level 4; asked lately: halves of a pizza; …)`. Goals not in the set send nothing.
  - **The global list:** "Recently asked" stays only for ideas with no goal (a map with no goals), at 30 days like the rest.
  - **What the server drops:** the picked goals' labels replace the 40 in the word and meaning checks. Due ideas are still exempt, so a missed idea can come back.
- **Car comparisons (`QUIZ_SYSTEM`, `check_questions`):** at most **one** question a set compares two of their cars.
  - A question that names two of the listed cars counts.
  - The first one is kept; any more go to spare.
- **The dice (`race.py`):** for each question slot, the server rolls a **format** and a **twist** with the desk's seeded `rng`.
  - **Formats** (`FORMATS`, 8):
    - how it works
    - compare two things
    - what happens if
    - odd one out
    - what comes next
    - closest guess
    - spot the rival's mistake ("a rival racer says …: what did they get wrong?")
    - a number from their interest
  - **Dealing:** formats are dealt from a shuffled deck, so a set has at least 4 different ones.
  - **Twists** (`TWISTS`, 5): a record (biggest, fastest, oldest), a bit of history, at home or school, a mystery to solve, and none ("would you rather" was dropped, below).
  - **In the prompt:** a numbered "Question plan" line lists each slot's format and twist.
  - **In the answer:** each question returns its `format`, an enum in `QUIZ_SCHEMA`.
  - **On disk:** the format goes in the results log and `stats.sqlite`. It's a fixed label, never question text.
  - **Spaced review:** a due idea's question gets a rolled format too, so it comes back in a new shape.
- **Write 15, race the 10 most different (`race.py`):**
  - **More written:** Claude writes **15** questions a set (`WRITE_SIZE`). `SET_SIZE` stays 10, and a set still covers 5 goals, now about 3 questions each.
  - **The pick:** after `check_questions` and before the blind check, `pick_varied` keeps 10:
    - questions on due ideas and probes first;
    - then, one at a time, the question least like its goal's 30 days of ideas and the ones already picked, compared by the meaning model;
    - ties go to a format not yet used.
  - **Without the meaning model:** it deals by format, so the set still varies.
  - **Cost:**
    - about 50% more output a write;
    - no extra Claude call;
    - the blind check sees all that passed (up to 15), so unpicked good ones can stand in for any it doubts (the review's suggestion).
  - **The meaning model's load:** it embeds about 200 short texts a write instead of about 60. I'll time that on throwaway data. If it's near the 10 s timeout, the history is cut to 20 a goal.
- **Questions ready each morning (the admin's addition, 2026-11-10):** "schedule a batch job to create these questions every day and have them pre-cached", so the student doesn't wait.
  - **When:** at start-up and each morning at 5:00 (`AHEAD_HOUR`), production writes up to 4 races' worth (`AHEAD_RACES`) for each supervised student, never past the day's races. After each race, the usual top-up keeps the next race ready.
  - **Where:** in the server's memory, like held questions today (the admin's choice). Rule 6 is unchanged, and a restart rewrites them at start-up.
  - **Time:** a write may take up to 150 s (`QUIZ_TIMEOUT_SECONDS`, up from 60). Real writes on made-up data took 72 s for 15 questions, against 25 s for 6 with main's prompt, and 87 s end to end.
  - **Freshness:** held questions that no longer fit (a set-aside, a changed goal or notes) are still dropped at the start of each race. Levels and due ideas are those of the morning.
- **The twist list:** "would you rather" was dropped after a real write: it read awkwardly.
- **Sameness numbers (numbers only):**
  - **The server log** gets one line per try, replacing today's "by meaning" line: `Race set: 15 written, 10 kept; dropped 3 repeats (1 by meaning), 1 set aside, 1 car; 7 formats`.
  - **`lerni stats USER`** gets a **Variety** line over the report's window: questions, distinct ideas, asked before (attempt > 1), and the formats used, most first.

No screen changes, so there's no mockup. Students see more kinds of questions, and the race looks the same.

## Tests (minimal, fakes only)

- **`tests/student/test_race.py`, a regression test for the loop:** a goal in box 2 that gets 1 of 2 right in a race moves to box 1, not box 0.
- **`tests/student/test_fresher_races.py` (new), the happy path:** a fake quizzer returns 15 questions, with a fake embedder.
  - The prompt carries each picked goal's own ideas from 20 days ago, and none of another goal's.
  - The prompt has a numbered question plan with at least 4 formats.
  - 10 are kept: the reworded twin and the second car comparison are dropped.
  - The log line is numbers only.
- **Safety, in the same file:** with an embedder that fails, a write still keeps 10, dealt by format.
- **The write-ahead, in the same file:** one prefill for 4 races holds at least 20 questions after 2 writes, and the next 5:00 is worked out right.
- **`tests/student/test_stats.py`:** one assert that `format` reaches the answers table and the Variety line.

**The eval (real calls, run by hand):** `scripts/eval_race.py` gains one case: a set uses at least 4 formats and compares cars at most once.

## Deploying

- **Safe to put on the home server while it's in use:** pull, reinstall, restart (a restart clears open conversations).
- **Nothing to set up.** The concepts file keeps its shape, and boxes move by the new rule from the next race. `stats.sqlite` gains its `format` column at the next nightly rebuild, or when `lerni stats` rebuilds it.
- **What changes for the family:** a question write takes a few seconds longer, though it runs ahead in the background. Goals the student does well on come back less often, which is intended.
