# v3.34: backups you can restore

**Goal:** The nightly copies leave the keys out, every data file is private to the admin's Mac account, a map and its journal are always copied as a pair, undo never reaches past a replaced map, and one command puts a nightly copy back, safely, while the family uses the app.

**Why:** the v3.7–v3.29 outside reviews (2026-10-27), confirmed then:
- the nightly copy holds `secret.key`, so anyone with a copy (a drive, `--to`) can sign in as anyone;
- data files and folders are readable by every account on the Mac (0644 and 0755);
- the copy can catch a map from one change and its journal from the next, so they disagree after a restore;
- undo skips the baselines a later rollback or restore leaves, so it can write old items over the replaced map;
- restoring is five manual steps, never tried.

**The admin's decisions (2026-10-30):**
- restore puts the whole data folder back, never one student; the folder it replaces is kept beside it;
- restore stops the server that uses the folder, swaps, and starts it again, after a confirmation.

**Not in this version:** a second backup place for a broken disk (Later in the to-do list); restoring one student.

## Changes

### 1. Keys stay out of the copies (`backup.py`)

- `run` leaves out `secret.key` and `https-key.pem`, beside `.tmp-*` and `*.lock`.
- **On a restore** they're carried over from the folder being replaced (§5), so nobody signs out and HTTPS keeps working.
- **From a copy with no folder beside it** (a broken disk): a new `secret.key` is made at the first start (everyone signs in again), and the admin makes the certificate again with mkcert (admin reference).

### 2. Private files (`jsonfiles.py`, `backup.py`, `web/serve.py`)

- `private(path)`: folders 0700 and files 0600, through the whole tree; a file it can't change is skipped and logged.
- **When:**
  - `lerni serve` sets `os.umask(0o077)` and runs `private` on its data folder at start, so new and old files alike are private;
  - `lerni backup run` and `restore` do the same, on the data folder and on `~/.lerni/backups/`.
- Nothing else reads these files, so nothing breaks: the server, the `lerni` commands, and the backups all run as the admin.

### 3. A map and its journal copied together (`journal.py`, `interests.py`, `backup.py`)

- `map_lock(maps, username)`: the per-map file lock the map store already takes (`maps/<user>.lock`), moved to `journal.py` so the backup can take it without the map code.
- `MapStore._locked` takes its thread lock, then `map_lock`, as today.
- **`run`** copies everything but `maps/` as today, then, for each user with a map or a journal, copies `<user>.json` and `<user>.events.jsonl` holding that user's lock. A change waits for the copy, or the copy waits for the change; never half of each.

### 4. Undo stops at a later baseline (`journal.py`)

- `undo(current, events, n)` refuses when a baseline comes after change `n`: the map was replaced outside the journal since (a restore, a rollback, a hand edit), so the journal can't say what changed.
- The message: "The map was replaced after change n (line m), so it can't be undone. To return to before it, rebuild with --upto n-1." Rebuild still works, from the baseline before `n`.

### 5. `lerni backup restore` (`backup.py`, `commands/backup.py`)

Mockup, the admin's terminal (no screen changes):

```
$ lerni backup restore
Copies of ~/.lerni/student, newest first:
  nightly-2026-10-30   3 accounts, 3 maps
  nightly-2026-10-29   3 accounts, 3 maps
  …
Restore one: lerni backup restore nightly-2026-10-29

$ lerni backup restore nightly-2026-10-29
This puts ~/.lerni/student back to nightly-2026-10-29 (3 accounts, 3 maps).
Everything since then is set aside, not deleted. prod restarts; open conversations end.
Restore? [y/N]: y
Stopped prod.
Restored nightly-2026-10-29.
The folder it replaced: ~/.lerni/student.before-restore-20261030-101500
Started prod.
```

- **Arguments:** a copy's name (or a path to one), `--data` (default production's folder), `--yes` to skip the question. No name lists the copies.
- `lerni backup run` gains the same `--data`, for the rehearsal on development's data.
- **Refuses**, changing nothing, when the copy has no `students/` folder, or isn't a folder.
- **Steps:**
  1. Find the server whose agent uses this data folder (prod or dev), and stop it if it's running.
  2. Copy the nightly folder to `<parent>/.restoring-<name>`; copy the keys and certificate over from the current folder; make it private.
  3. Rename the current folder to `<name>.before-restore-<YYYYMMDD-HHMMSS>`, then the restored one into place.
  4. Start the server again if it was running, and wait until it answers.
- **If a step fails:** before step 3, the half copy is removed and the server started again, with nothing changed. Between the two renames (a crash), the message names both folders, and the admin renames the kept one back.
- The kept folder is never deleted by Lerni; the admin deletes it when sure.

## Deploying

Safe while in use. Pull, reinstall, and restart production; a restart clears open conversations. The first start makes the data folder private, and the next nightly copy leaves the keys out (older copies still hold them: the admin can delete `secret.key` and `https-key.pem` from them by hand). Install the backup agent again (`lerni backup install`) only if its log shows it can't read the folder; it runs as the same account, so it shouldn't.
