# v3.41: a failed Claude call says why

**Goal:** When Claude can't be reached, and above all when Claude Code's sign-in on the home server has expired, the server log says why, and educators see it at once.

**Why (2026-11-09):** right after v3.40 shipped, races said "The track needs a minute" and nothing reached the log. The cause was Claude Code's sign-in on the home server, which had expired: "OAuth session expired and could not be refreshed". Every Claude feature was down (Chat, the tagger, Upload, the Suggest box, areas, bonus grading), and the only clue was that friendly line. The admin chose: log it, and tell educators.

## What changes

- **`Usage` (`usage.py`), which every Claude call already shares:**
  - **`failed(signin: bool)`** notes a failed call. A sign-in failure marks Claude as signed out.
  - **`succeeded()`** clears that mark.
  - **`warning()`** puts the signed-out line first: `⚠️ Claude needs the admin to sign in again.` It already shows to educators only, at the top of their page.
- **The adapter (`adapters/claude_code.py`), in one helper used by every failure path** (Chat's `stream`, `tag`, `write`, `propose`):
  - It looks through the error and its causes for a sign-in failure ("authenticate", "OAuth", "login"), then calls `usage.failed`.
  - It prints one line: `Claude call failed (race questions): sign-in expired`, or the error's kind (`TimeoutError`, `ProcessError`). It never prints the error's text, a prompt, or an answer.
  - A call that returns a result calls `usage.succeeded()`. So after the admin signs in, the next call clears the line, with no restart.
- **Students and their messages** stay as they are ("The track needs a minute", "Claude didn't answer"): the fix is the admin's, not theirs.
- **Docs:**
  - `docs/reference/admin.md` gets a troubleshooting line: the log says `sign-in expired`, so run `claude` in Terminal, then `/login`.
  - `docs/ARCHITECTURE.md`'s outbound line.

## Tests (minimal, fakes only)

- **`tests/student/test_claude_code_adapter.py`, the happy path:** a faked `query` that raises an error caused by "Failed to authenticate: OAuth session expired":
  - the quizzer still raises `RaceUnavailable` with today's message;
  - the log line says `sign-in expired` and holds no prompt text;
  - `usage.warning()` shows the sign-in line;
  - the next call that succeeds clears it.
- **`tests/student/test_usage.py`:** one assert, that the sign-in line comes before a near-limit line.

No prompt changes, so no eval.

## Deploying

Safe to put on the home server while in use: pull, reinstall, restart (a restart clears open conversations). Nothing to set up. If the log ever says `sign-in expired`, run `claude` in Terminal on the home server and `/login`. No restart is needed after that.
