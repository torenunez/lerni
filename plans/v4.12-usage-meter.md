# v4.12: usage meter, minimal CI, and secret scanning

**Goal:** see what each Lerni feature costs against the Claude plan's limits, check every PR automatically, and make sure no secret was ever committed ([longer sessions](longer-sessions.md), [to-do](../docs/todo.md#upcoming-versions)).

## The admin's calls (2026-11-10 to 2026-11-12)

- **The meter comes first** of the longer-sessions work, so everything after it is measured. A week of data may reorder the rows after it.
- **CI before Version 5:** on each PR, GitHub Actions runs only a few key integration tests (fakes only, no secrets, never an eval), marked in the suite, plus lint on changed files. The full suite stays in the commit gate.
- **Secret scanning:**
  - first a read-only `gitleaks` scan of the whole history, redacted, reported as file, short commit, rule, and date, each judged real or a false positive;
  - a real one is named so the admin rotates it first; history is rewritten or force-pushed only on the admin's word after that;
  - false positives go in `.gitleaksignore` by fingerprint;
  - then a `secrets` CI job copied from the admin's own check workflow;
  - a pre-commit hook is shown, not added, unless the admin says so.

## Part 1: the usage meter

- **What each Claude call records, numbers and labels only** (rule 6): the day and time, the use, the model, input, output, and cached tokens, seconds, whether it failed, and the 5-hour and weekly window shares after it.
- **Where:** `usage/<day>.jsonl` in the data folder. No usernames, no text. Kept 90 days (my call: enough for trends, small).
- **The use, by name** (my call): a context the calling code sets, `with using("race-write"):`, read by the adapter when it records. Code with no label records the adapter's kind (chat, tagger, small model, upload). The uses:
  - `chat-supervised`, `chat-independent`, `tagger`;
  - `race-write`, `race-check`, `bonus-grade`;
  - `area-sort`, `morning-plan`, `spelling-words`, `upload`, `educator-chat` (the Tell Lerni box too), `tell-lerni-check`, `feedback`.
- **`lerni stats`** gains "Claude use by feature", for today and the last 7 days: calls, tokens in and out, seconds, failures, and each feature's share of the windows' movement (a call's share is how far a window moved since the call before it, so a feature that keeps both windows still costs nothing).
- **Code:**
  - `meter.py` (new, standard library): `using(name)`, `UsageLog` (append, read a range, prune past 90 days);
  - `adapters/claude_code.py`: after each `ResultMessage`, one record with its `usage` and `duration_ms`, and the windows `Usage` holds right then;
  - the call sites: one `using(...)` each;
  - `stats.py` and `commands/stats.py`: the table.
- **Test:** one call through a fake records one line with its use and tokens, and no prompt or reply text.

## Part 2: minimal CI

- **`.github/workflows/check.yml`**, on pull requests to `main`:
  - **lint:** ruff on the Python files the PR changes (`src/` has known debt, so not everything);
  - **tests:** `pytest -m ci`, a few key integration tests marked `@pytest.mark.ci`: the race (typed slots and choices), sign-in and roles, rule 6 (nothing typed on disk), the meter, and the code manifest.
- **No secrets and no network in CI:** tests use fakes; the private-words file isn't in the repo, so that test checks only the mechanism.
- **The mark** is registered in `pyproject.toml`; the commit gate still runs the full suite.

## Part 3: secret scanning

1. **Install `gitleaks`** with Homebrew (asked first).
2. **Scan the whole history**, redacted, read-only; report each finding as file, short commit, rule, and date, judged real or false positive.
3. **A real one:** stop and name it, so the admin rotates it; nothing is rewritten without the admin's word.
4. **False positives** go in `.gitleaksignore` by fingerprint.
5. **The `secrets` job** in `check.yml`, copied from the admin's own workflow (`~/Development/agent-skills/.github/workflows/check.yml`): `actions/checkout@v7` with `fetch-depth: 0` and `persist-credentials: false`, `gitleaks/gitleaks-action@v3`, `permissions: contents: read`. It needs no license secret while the repo belongs to a person; stop if it moves to an organization.
6. **A pre-commit hook** is shown in the PR, not added.
