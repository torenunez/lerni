# v4.1: repeats by theme, and where embeddings help (decided)

**Status:** decided by the admin on 2026-11-10, after an internal review and two outside reviews.

**The problem:** race questions keep returning to the same few themes for a goal, even when each question's idea is new.

## What's in place

- **Checks by meaning (v3.40):**
  - **Repeats:** a question is dropped if its idea's label is 0.91 or closer to a recent label.
  - **Set-asides:** a question is dropped if it's 0.55 or closer to a set-aside interest.
- **The recent labels for the repeat check:**
  - every picked goal's "asked lately" list, pooled together (30 days, up to 30 a goal, so busy goals have a shorter window);
  - plus the labels of held and kept questions.
- **Fresher races (v3.42–v3.43):**
  - 15 questions are written and the 10 most different are kept;
  - each question is dealt a format, a twist and a setting;
  - every interest takes turns;
  - the morning plan adds steps for each goal.
- **Calibration:** 103 made-up pairs (50 repeat pairs, 53 set-aside pairs) and a bake-off script.

## Why the 0.91 check can't catch theme repeats

- **The check embeds only the idea's label.** Different ideas on one goal score high together, so same-theme questions pass, by design.
- **The figures behind the cut come from two different sets:**
  - a full paraphrase scored 0.70 on a made-up pair;
  - two different ideas on one goal scored up to 0.90 in an unsaved check on real labels.
- **So the cut has no margin and can't be reproduced.** Lowering it would drop questions that really are new angles.

## Causes found

| Cause | Where | Kind |
|---|---|---|
| The dealt frames lean towards size and speed: 3 of 8 formats are about quantities, and the twist "a record (biggest, fastest, oldest)" is drawn for about 1 slot in 5 | `race.py` `FORMATS`, `TWISTS` | Theme |
| The prompt's only example label is "top speed vs acceleration", and it asks for a different *idea*, never a different angle | `race.py` `QUIZ_SYSTEM` | Theme |
| Interests are counted across all goals, so goals and interests can fall into step: one goal gets the same interest for every question in a set | `race.py` `deal`, `concepts.settings_since` | Theme |
| An educator's connection leads 2 of a goal's 3 slots, for up to 30 days | `race.py` `deal`, `morning.py` | By design |
| At most one car comparison a set, using 0-60 time, horsepower or price; the count resets on the second try | `race.py` `QUIZ_SYSTEM`, `check_questions` | Theme |
| Missed ideas come back after 1, 3 and 7 days | `concepts.py` | By design |
| **Bug:** a math label loses its operators and signs, so "1/2 + 1/4" and "1/2 − 1/4" are one idea, and their questions share one hash | `concepts.normalize`, `results.question_hash` | Identity |
| **Bug:** the repeat check pools goals, so an idea asked on one goal blocks its first use on another | `race.py` `_write` | Identity |
| **Bug:** a reworded review doesn't advance its idea, which stays due and keeps coming back | `race.py` `_as_due` | Identity |
| Repeats race when Claude can only repeat | `race.py` (`spare`) | Rare |
| A timed-out embedder quietly switches the checks by meaning back to words | `llama_embed.py` | Rare |

## Decision (the admin, 2026-11-10)

- **Fix the causes now, without embeddings, and measure alongside (not as a gate).**
  - **v4.2, race fixes:**
    - keep the math in labels and question hashes, with stable goal-scoped ideas;
    - check repeats within each goal;
    - give each review an id that Claude returns, so a reworded review advances the right idea;
    - drop the prompt's example label, and add "a different idea and a different angle, never the same measurement in other words";
    - at most one quantity format per goal and one "record" twist per set;
    - start each goal's interest turns at a different group;
    - never compare the same car number twice in a row, counted across both tries.
  - **The private repeat report:** existing labels and counts, shown on the admin's screen and never committed. Goal-by-setting counts follow once settings have a week of data.
- **Theme clustering by embeddings (option C) is dropped.** Within one goal, a cluster at 0.8 would take in most of the goal.
  - **If the fixes don't land:** a short `theme` label on each question, counted exactly by the server ("asked a lot lately: sizes ×6").
  - **If embeddings are ever used for themes:** subtract the goal's own direction first, and calibrate on a private saved set of real labels.
- **Learned ideas:** an idea right every time, at least twice, leaves races but stays open for Version 6 recall, on its own list rather than "asked lately".
- **Versions 5–7:**
  - Version 5 is built switched off until it has enough probe data;
  - Version 6 is designed, then built once a goal's checked bank holds about 8;
  - Version 7 is its own release, after a written safety plan;
  - minimal CI moves from Version 8 to before Version 5.
- **Pending:** what Version 4 keeps on disk (the ✗'d question's record, and the day's sample for 7 days). Both are recommended, and both need a rule 6 change.

## Embedding uses

- **Kept:**
  - **v4.4, the banked question:** its label joins the repeat check within its goal, so no fresh question on the same idea races beside it. The repeat check mustn't block the banked question itself.
- **Deferred, each until a need is seen:**
  - **Version 5:** drop a suggested goal that repeats an existing one. Ids, aliases and Claude's view of the goals come first.
  - **v4.5+:** answer keys already in the bank.
  - **Version 6:** examples from the checked bank, and recall neighbours.
  - **Version 7:** the set-aside check on the morning plan and Upload, as an extra layer only.
- **Dropped:**
  - **A diverse audit sample:** the sample is weighted on purpose, which makes it a work queue, not an error-rate estimate.
  - **Flags for wrong choices too close to the answer:** the blind check is stronger.
  - **Routing guidance by meaning:** the Tell Lerni agent does it, and a person ticks.
  - **Comparing whole question texts.**
  - **Embeddings as a safety guard:** they catch about 63% of close set-aside pairs.
- **Kept as test cases:** numbers and negation pairs in the bake-off, since 50 repeat pairs only calibrate. They don't guarantee anything.
