# v3.17 Practice on the map: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** What races learn shows on the map, read-only:
- **Goals:** a goal's details show a **Practice** line: last raced, this week's right out of asked, and ideas missed lately.
- **Links:** links remember every day they came up, so related items and bridges get a strength.
- **Bridges:** each bridge says how it held.
- **Groups:** a group shows its kinds' bridges.

**Architecture:**
- **Link days (`interests.py`):**
  - **The new field:** `Link.days: list[str]`, the sorted days the two items came up together.
    - `Link.day` stays as the latest day, because `put_back` orders links by it and the list is kept in order of recency.
    - `__post_init__` sets `days = [day]` when it's empty, so every old map loads with one day and no load code changes. Maps upgrade on their next write.
  - **Adding to a link:** `_link` keeps an existing link's days and adds today's, instead of replacing the link.
  - **Merging:** `_merge` joins the days of two copies of a link that become one.
  - **Put back:** restores a link's `days` from Removed (older Removed entries have only `day`).
- **Link facts (`interests.py`):**
  - **Strength:** `link_strength(link, today)` uses the item rule (`strength`'s thresholds over 30 days), from `link.days`.
  - **A bridge's record:** `bridge_record(m, link) -> (held, bounced)`:
    - **held:** `len(link.days)`;
    - **bounced:** the bridge's goal's bounces that fall on those days.
  - **In the details:** `Details.ties: dict[tuple[str, str], tuple[str, int, int]]`, keyed by (link kind, other id), giving (strength, held, bounced) for each related item and bridge.
  - **Groups:** `details` collects bridges across `family(m, e)`, so a group lists its kinds' bridges, as `group_days` does for days.
- **The Practice line (`results.py`):**
  - **The call:** `ResultsLog.practice(username, goal_id, today) -> Practice | None`, a frozen dataclass:
    - `last` (ISO day);
    - `right`, `asked` (last 7 days);
    - `missed`: up to 3 concepts on this goal answered wrong in the last 14 days and not answered right since, newest first.
  - **No races:** with no answers on the goal, it returns None.
  - **Where it reads:** only the results log (answer lines carry `goal_id` since v3.14). Nothing is stored.
- **Screens (`web/mentallist.py`, `web/maps.py`, `web/educator.py`):**
  - **Wiring:** `mental_list(…, results=None)` takes the results log; both screens pass `races.results`, or `None` when Claude is off.
  - **A goal's facts** gain the line `Practice: raced 2026-10-20 · this week 7/10 · missed lately: halves of odd numbers` (only the parts that apply).
  - **Each Bridges and Related button** reads `→ volcanoes 💪`; a bridge adds `· held 5 days · bounced once`.

**Tech Stack:** Python 3.11+, Gradio 6.30 (`gr.render`, existing), pytest.

**Spec:** [spec 09b](specs/09b-harder-races.md), "Practice on the map (v3.17)" and "Practice and link days".

## Global Constraints

- **Rule 5:** nothing here writes a goal or changes the map from the results log; the Practice line is read each time it's drawn.
- **Rule 6:** the line shows concept labels and numbers only.
- **Old maps** load unchanged and draw the same; a link from before v3.17 counts as 1 day.
- **Tests:**
  1. `test_interests.py`, `test_links_keep_their_days_and_bridges_say_how_they_held`:
     - an old map's link (a dict without `days`) loads with `[day]`;
     - a second tagged day makes it growing;
     - a bounce on one of its days counts against the bridge, and one on another day doesn't;
     - a merge joins the days;
     - a group's details list its kind's bridge.
  2. `test_race.py`: the existing results test also checks `practice()`: the right count, the 7-day count, and a missed concept that a later right answer clears.
- **Screen check:** as an educator with both MentalMap lists, right after a restart, at phone size (CLAUDE.md rule 9), on a throwaway localhost server with generated test accounts deleted afterwards. A goal's Practice line and a bridge's record must show.

## Review Focus

1. **Two bridges to one goal on the same day:** a bounce counts against both. Acceptable: the tagger records a bounce on the goal, not on a bridge.
2. **A merge or Put back with links from before v3.17:** days come through, with no duplicate days.
3. **A results log with lines from before v3.14** (no `goal_id`): they're skipped, never a crash.
4. **The educator's view of a supervised student:** the Practice line reads the student's results, never the educator's own.
5. **Rendering cost:** the results log is read once per draw, not once per goal.
