# v3.14 Right answers, and a results log: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- **Right answers:** a race question never teaches a wrong answer.
  - The server works out arithmetic answers itself.
  - A second, blind Claude call answers each question, and a disagreement drops it.
- **A results log:** every race answer is logged as labels and numbers, kept for good. It's the data later versions need for difficulty, spaced review and probes. The educator sees, per goal, how many were right this week.

**Architecture:**
- **Worked-out arithmetic (`race.py`):**
  - The quiz schema gets an optional `math`: when the right answer is a number worked out from the question's numbers, Claude writes the sum (for example "400 / 2", "3 / 4 * 12").
  - `check_questions` evaluates it safely: an `ast` walk allowing only numbers, `+ - * /`, parentheses, and unary minus.
  - It drops the question if the keyed choice's number (an integer, a decimal, or "3/4") isn't that value.
  - A choice that isn't a number, or no `math`, skips this check.
- **The blind check (`race.py`, `adapters/claude_code.py`):**
  - `RaceDesk` takes an optional `checker` (the same small-model adapter; `None` in most tests).
  - **What Claude gets:** after a write, one call with `CHECK_SYSTEM` and `CHECK_SCHEMA` (`{"picks": [0-2, …]}`) receives the questions and choices only, never the key or the why. It returns its pick for each.
  - **What's dropped:** a question whose pick differs from the key. The good questions from both tries still count together.
  - **If the check call fails,** the set races unchecked (written to the server log as a count, never text): a race beats no race, and the arithmetic check still applies.
  - **The adapter:** `ClaudeCodeQuizzer.write(system, prompt, schema=QUIZ_SCHEMA)`. Same usage pause and timeout.
  - **Cost:** about one more small call per 10 questions.
- **The results log (`results.py`, new):** `<data>/results/<user>.jsonl`, one line per answer and one per finish.
  - **Each answer:** `{"day", "race", "goal_id", "goal", "concept", "q": <12-hex hash of the normalized question>, "right": bool, "seconds"}`. Seconds are measured from when the question was shown: the race start for the first, the last answer after that.
  - **Each finish:** `{"day", "race", "place", "points", "version"}`.
  - **What it never holds:** question or answer text (rule 6). The goal and concept are labels.
  - **Lifetime:** kept for good.
  - **Writes:** best effort; an `OSError` never stops a race.
  - **`week(username, today)`** gives `[(goal, right, asked)]` for the last 7 days, newest goal first.
- **MentalMaps:** the student's ⭐ line adds "This week: Fractions 7/10 · Acceleration 4/5" (`student_points` gets the results log).

**Tech Stack:** Python 3.11+ standard library (`ast`, `hashlib`), pytest; `scripts/eval_race.py` (real Claude calls, by hand).

**Spec:** [spec 09](specs/09-play-and-points.md) ("Questions", "Rules that still hold"). The admin's decisions of 2026-10-19:
- the answer-key checks and a numbers-only results log ship together;
- the results log is kept for good.

## Global Constraints

- **Rule 6:** no question or answer text on disk, only a hash, labels and numbers. CLAUDE.md rule 6 lists race results.
- **No `eval`:** the arithmetic is an `ast` walk with a whitelist.
- **Tests:** two new tests in `test_race.py`. Each covers a safety guarantee:
  1. a wrong key never races (arithmetic and the blind check);
  2. answers are logged as labels and numbers, with the weekly summary.

  The fakes stay as they are (`checker=None`).
- **Eval:** two wrong-key cases: a sum keyed wrong, and a concept keyed wrong. The real check catches both.

## Review Focus

1. **The blind check disagreeing with a right key** (a real ambiguity): the question is dropped, which is fine. Too many drops fall back on today's top-up rules; a race is never refused because of the check alone.
2. **Choices that are numbers with units** ("200 meters"): the leading number is compared.
3. **Order:** the check's picks match the questions after the choices are shuffled. The checker sees the shuffled choices.
4. **A results file growing over a year** (about 50 lines a day): `week()` reads only recent lines from the end, or reads it all at family scale. Fine either way; say which.
5. **An educator racing:** their results are logged under their own name and shown nowhere (MentalMaps shows supervised students only), never on a student's.
