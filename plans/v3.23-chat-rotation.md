# v3.23 Chat's goals take turns: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every goal gets regular days in Chat. Today Chat shows Claude the 8 goals with the fewest bridges and explanations. When more than 8 are tied on that score, the oldest always win, so newly added goals can wait weeks. On the supervised student's map, 15 goals are tied at zero, and 7 of the 8 goals added on 2026-10-22 never reach Chat.

**Architecture (`interests.py`, `map_block` only):**
- **Still the 8 least-covered goals** (bridges + explained days), minus any backed off. That rule doesn't change.
- **Ties take turns by day:** among goals with the same score, the order comes from a fingerprint of the day and the goal's id: `_turn(day, goal_id) = sha256(f"{day}|{goal_id}")`.
  - **Within a day, the order is the same,** so a conversation's goals don't jump around between messages.
  - **Across days, it's reshuffled,** so every tied goal is in view about 8 days in every 15 here.
  - **No new state:** nothing is stored, and the map file doesn't change.
- **Goals with a higher score** still come after all lower-scored ones, as today.

**Tech Stack:** Python 3.11+ standard library (`hashlib`), pytest.

**Spec:** [spec 04](specs/04-interest-map.md), the conversation's map block ("up to 8 goals … those with the fewest bridges and explained days first"). The admin's decision of 2026-10-22.

## Global Constraints

- **Rule 5:** steering changes nothing on the map; only people set goals.
- **The map block stays at most 1,500 characters,** with the set-asides line first.
- **Tests:** one test, `test_interests.py`, `test_tied_goals_take_turns_in_chat`:
  - with 15 goals at zero coverage, the 8 shown are the same all day;
  - over 14 days, every one of the 15 is shown at least once;
  - a goal with a bridge still comes after every zero-coverage goal.

## Review Focus

1. **Determinism:** the same day and map always give the same 8, across server restarts. Python's `hash()` changes per process, so it isn't used.
2. **Fairness:** over a month, no tied goal is left out much more than the others (check the spread in the test's data).
3. **A resting goal** (backed off after bounces) stays out, as today.
4. **The tagger reads the same block,** so its view of goals matches Chat's.
5. **Maps with 8 or fewer goals** show all of them, exactly as today.
