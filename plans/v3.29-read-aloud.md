# v3.29 Read-aloud questions: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A race question can be heard, not only read. A 🔊 button reads the question and its three choices aloud. A **Read aloud** switch reads each question by itself as it appears.

**Why (2026-10-24):** the student knows some words by ear better than by sight. The admin's decision: a 🔊 button plus an auto switch, using Chat's voice.

**Architecture:**
- **Speaking a question (`race.py`):** `RaceDesk.read_aloud(username, race_id, number) -> bytes | None`.
  - **Only the question on screen:** the race must be this person's, and `number` the question showing. Anything else gives None (a stale or forged tap).
  - **What it says** (`spoken_question(race)`):
    - a multiple-choice question: "Question 2. ⟨question⟩ A: ⟨choice⟩. B: ⟨choice⟩. C: ⟨choice⟩.";
    - the bonus: "Bonus question. ⟨question⟩".

    It's cleaned with `voice.for_speaking`.
  - **Who speaks:** the server's `Speech` (`say` on the home server).
  - **Cached** in memory per race and question number, so a second tap doesn't speak again. The cache is dropped with the race. Audio and text never go to disk (rule 6).
  - **If the voice fails** (`SpeechUnavailable`): None, and the card stays as it is.
- **The screen (`web/games.py`, `web/race.js`, `web/talk.js`):**
  - **The 🔊 button** sits on the question card's first line, shown only when the server has a voice and a question (or the bonus) is showing.
  - **A tap:**
    1. unlocks the player inside the tap (`lerniTalk.unlock`, newly exported), as iPad Safari needs;
    2. the server returns the clip into a hidden field;
    3. `lerniTalk.play` plays it.
  - **The switch:** "📖 Read aloud", a small toggle beside 🔇 under the track. It's remembered on this device (`localStorage`, a setting only, like 🔇).
    - When on, `race.js` presses the hidden 🔊 each time a new question appears, keyed by race id and number, so a redraw doesn't repeat it.
    - Race! and the answer taps unlock the player, so later questions play without another tap.
  - **🔇 stops the race sounds only;** read-aloud has its own switch.
  - **A new tap stops the current reading** (`lerniTalk.stop`) before answering, so voices don't overlap.

**Tech Stack:** Python 3.11+, Gradio 6.30, vanilla JS, pytest.

**Spec:** [spec 09b](specs/09b-harder-races.md) ("Not in this version" listed read-aloud; this adds it). The admin's decisions of 2026-10-24.

## Global Constraints

- **Rule 6:** question audio and text stay in memory only; the device remembers only the switch.
- **Rule 9:**
  - checked at phone size;
  - the admin checks sound and autoplay on the iPad (iPad Safari's play rules can't be checked in the built-in browser).
- **Cost:** no Claude calls; `say` runs on the Mac, about a second per question.
- **Tests (rule 4):** one in `test_race.py`, `test_a_question_is_read_aloud_once_and_only_on_screen`:
  - the fake speech hears the question and its three choices;
  - a second call uses the cache;
  - a stale number, another race's id, or another person gets None;
  - the bonus reads "Bonus question.".

## Review Focus

1. **A reading still playing when the student answers:** it stops, and the next question's reading (auto) starts cleanly.
2. **The switch on, with no voice on the server:** no 🔊, and nothing is pressed.
3. **After a wrong answer** (the card shows the why and waits for Next): auto doesn't re-read the old question; 🔊 then reads the next question once Next shows it.
4. **Emoji and math in a question** ("¾ of 12 🍕"): spoken sensibly, emoji dropped.
5. **Two quick 🔊 taps:** one clip, one playback.
