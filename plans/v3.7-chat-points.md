# v3.7 Points in Chat: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A real answer to Lerni's question in the conversation earns ⭐, adding to the same total as the race:
- ⭐ +3 for a right answer;
- ⭐ +1 for a real try in their own words;
- nothing for emojis, "idk", or a change of subject.

Ask is renamed Chat. Tapping ⭐ in the header explains the two ways to earn.

**Architecture:**
- **The tagger** already runs after every exchange and already sees Lerni's message before it. It gets one more field, `answered`.
- **The map keeper** turns `answered` into an award, once per exchange, through the existing `PointsStore.award(…, "chat", …)`. That call already holds Chat to 30 a day.
- **The header ⭐** becomes a button. A tap opens a short "How to earn ⭐" (in the page, with no server call). After each answer, a short timer refreshes the total for a few seconds, so "⭐ +3" shows up.
- **Lerni** never decides points; one fixed rule says it may invite answers for ⭐.

**Tech Stack:** Python 3.11+, Gradio 6.30 (`gr.Timer`), pytest.

**Spec:** [spec 09](specs/09-play-and-points.md): "Chat", "Chat points", the Numbers table, and the header line. These are the admin's decisions:
- Chat stays conversational, with no multiple choice (2026-10-12);
- tapping ⭐ explains how to earn (2026-10-14).

## Global Constraints

- **Points:**
  - `right` 3, `tried` 1;
  - Chat is held to 30 a day by `PointsStore`;
  - the award id is `chat-<exchange id>`, applied once.
- **No award:**
  - for a skipped exchange (excluded, personal, scary);
  - for a stopped answer;
  - after New conversation (`is_current()` false).

  An award still applies when the map update is stale because a person edited the map meanwhile (spec 09).
- **Lerni never promises or counts points.** The fixed rule says only that good answers earn ⭐. No screen says "wrong".
- **Rule 6:** points files hold ids and numbers only. The 7-day log already records the tags, which now include `answered`.
- **Rule 5:** nothing here touches goals.
- **The rename:** on screens, "Ask" becomes "Chat" for independent students, and the supervised screen's menu item "Lerni" becomes "Chat" too, so "answer in Chat" matches the menu. Internal ids (`ask`, `home`) stay, so nothing else breaks. Current-state docs say Chat; history stays as written.
- **The explainer** shows only for players (supervised students and educators), the same as ⭐:
  - "**How to earn ⭐**";
  - "🏁 **Race** in Games: get answers right to win.";
  - "💬 **Chat** with Lerni: answer its questions in your own words. ⭐ +3 for a right answer, ⭐ +1 for a good try."
- **Tests (rule 4):** one tagging test (the award applies once, holds to the cap, and never on skip, stop, or a cleared conversation), plus 2 eval cases by hand.

## Review Focus

- **A student who answers with emojis or "idk"** gets nothing, and nothing says "wrong". This is the tagger's job, so it's checked by the eval cases in Task 4.
- **New conversation** tapped while the tagger is still running gives no award. Task 1's test covers it.
- **The same exchange tagged twice** (a retry) awards once. Task 1's test covers it.
- **The header ⭐ on a phone:** the tap target is at least 44 px and the explainer doesn't push the chat off screen. Checked by hand in Task 3.
- **The timer** stops by itself after about 10 s and never runs when nobody is answering. Checked by hand in Task 3.

```python
def test_a_real_answer_earns_stars_once_and_never_when_skipped_stopped_or_cleared(tmp_path):
    from lerni.student.points import CHAT_CAP, PointsStore

    points = PointsStore(tmp_path)
    tags = {"answered": "right"}
    keeper = MapKeeper(MapStore(tmp_path), FakeTagger(tags), None, run=lambda work: work(),
                       points=points)
    ex = Exchange("sam", "What makes it speed up?", "the engine pushes", "Yes!", False,
                  lambda: True)
    keeper.after(ex)
    keeper.after(ex)  # tagged again: the same exchange awards once
    assert points.get("sam").balance == 3
    tags["answered"] = "tried"
    keeper.after(Exchange("sam", "Why?", "maybe the wheels", "Close!", False, lambda: True))
    assert points.get("sam").balance == 4
    for skipped, stopped, current in (("scary", False, True), (None, True, True),
                                      (None, False, False)):
        tags.update(answered="right", skip=skipped)
        keeper.after(Exchange("sam", "Q?", "an answer", "A", stopped, lambda c=current: c))
    assert points.get("sam").balance == 4  # skipped, stopped, or New conversation: nothing
    tags.update(answered="right", skip=None)
    for _ in range(20):
        keeper.after(Exchange("sam", "Q?", "an answer", "A", False, lambda: True))
    assert points.get("sam").balance == CHAT_CAP  # Chat stops at the day's cap
```

- [ ] **Step 2: The "+3" after an answer:**
  - `ask_tab` returns `(tab, chat, voice, done)`, where `done` is its list of answer events (typed and spoken).
  - In `main.py`, `watch = gr.Timer(2, active=False)` and `before = gr.State(0)`.
  - For each event in `done`: `.then(start_watch, None, [watch, before])`. `start_watch` reads the viewer's balance into `before` and activates the timer.
  - `watch.tick(on_tick, [before, ticks], [stars, watch, ticks])`:
    - when the balance is above `before`, show `⭐ N  +k`, then stop the timer;
    - otherwise stop after 5 ticks (10 s).
  - Players only. For anyone else `start_watch` leaves the timer off.
