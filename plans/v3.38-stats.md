# v3.38: data you can query

**Goal:** The admin can ask the student data real questions, with SQL or one command, without reading files by hand.

**Why (the admin, 2026-11-03):** the only summary today is the weekly card on the educator's page. Maps, results, and concepts sit in one file per student, so "how is Math going over a month?" or "which ideas get missed most?" has no answer. Embeddings and suggested goals also need numbers to be judged by.

## What changes

- **`src/lerni/student/stats.py` (new): the copy.** `build(root) -> Built` reads the data folder and writes `<data>/stats.sqlite`, standard library only.
  - It's rebuilt whole every time: never edited, never the source of truth, no migrations. It's written to a temporary file and swapped in, so a reader never sees half a copy, and it's private to this account (`0600`).
  - A line cut short by a write in progress is skipped and counted, never fatal.
- **The tables:**

| Table | One row per | Columns |
|---|---|---|
| `students` | account | username, kind, educator, archived |
| `entries` | goal or interest | username, entry id, kind, name, area (a goal's heading: no area is `Other`), mentions, days, explained days, state (`active`, `resting`) |
| `answers` | answered question | username, day, week, race, goal id, goal, area, concept, question hash, level, attempt, right, seconds, probe, bonus tier |
| `races` | finish | username, day, week, race, place, points |
| `probe_taps` | tap on a probe topic | username, day, topic |
| `concepts` | idea in the ledger | username, goal id, goal, concept, first, last, asked, right |
| `goal_levels` | goal | username, goal id, level, box, due |

  - `area` comes from the goal's id, so a renamed goal keeps its rows; a goal no longer on the map shows `Other`.
  - Older lines have no level or attempt: those are empty, not guessed.
  - **Never copied:** conversation logs, feedback, goal notes, display names, passwords, and keys.
- **`lerni stats` (`src/lerni/commands/stats.py`, new):** it rebuilds the copy first, so its numbers are always current (the data is small), then prints.
  - `lerni stats`: one line per student.
  - `lerni stats USER`: the report below. `--weeks N` sets the window in whole weeks, this one included (default 4); `--all` takes everything.
  - `lerni stats --sql "SELECT ..."`: any query, on a read-only connection.
  - `--data` picks the folder, as `lerni backup` does (default production's).
- **Honest numbers:** each percentage shows its count and a 95% range (Wilson), since most goals have few answers. Goals with fewer than 5 answers are left out of the "hardest" list. Probes count only in their own line, and bonus tiers aren't right or wrong, so neither moves a goal's percentage.
- **Nightly:** `lerni backup run` also rebuilds the copy, so `sqlite3 -readonly <data>/stats.sqlite` is at most a day old without running anything. A failed rebuild never fails the backup. Backups skip the file, because it can always be rebuilt.

## Tests (minimal, fakes only)

- `tests/student/test_stats.py`:
  - the happy path: a small data folder builds every table; a renamed goal keeps its area; a cut-off line is skipped and counted;
  - the safety test: markers placed in a conversation log, feedback, goal notes, and a display name never appear in the file, which is private;
  - the read-only guarantee: a `--sql` write is refused;
  - the Wilson range against a known value.
- `tests/student/test_backup.py`: one more assert: the copy leaves `stats.sqlite` out, and a failed rebuild doesn't fail the backup.

No prompts change, so no eval.

## Deploying

Safe to put on the home server while it's in use: pull, reinstall, restart (a restart clears open conversations). The app itself doesn't change. The first `lerni stats`, or the next 03:00 backup, makes `stats.sqlite`. The nightly backup needs no reinstall, because it runs the `lerni` in the production checkout.
