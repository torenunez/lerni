# v3.9 No repeated questions: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Race questions stop repeating. The admin saw the same or nearly the same questions race after race in production.

**Why it happens:** every Claude call gets the same goals and interests and no memory of what was asked, so with 5 calls a day (10 races, 2 per call) it writes much the same set each time. The prompt's example ("acceleration with race cars") also pulls questions toward one angle.

**Architecture:**
- **A concept on every question.** The quiz schema gets `concept`: a short label for the one idea the question tests ("0–60 vs top speed"). It's checked like a name and never shown to the student.
- **Concepts are remembered.** A new store, `concepts.py`, keeps each player's recently asked concepts in `<data>/concepts/<user>.json`, as labels, goals and dates only, for 14 days (the last 40). A concept is recorded when its race starts, not when it's written. Later versions add review dates (v3.18) to the same file.
- **Claude is told.** `quiz_input` lists them: "Recently asked, choose other ideas or angles: …".
- **The server drops repeats.** `check_questions` takes what to avoid and drops a question when:
  - its concept matches a recent or held one (normalized);
  - its text is nearly the same as one asked or held since the server started, or as another in the same set (`difflib` ratio ≥ 0.8, kept in memory only);
  - it repeats another in the set.
- **Fewer good questions are still enough:** `_write` keeps the good questions from both tries, not just the last, before saying "The track needs a minute".
- **More variety:** the prompt asks for a different idea and angle per question (how it works, compare two things, what happens if, a number from their interest), and its example no longer names one interest.

**Tech Stack:** Python 3.11+ standard library (`difflib`), pytest.

**Spec:** [spec 09](specs/09-play-and-points.md) ("The race", "Rules that still hold"); the admin's decision of 2026-10-19: the *idea* is remembered, never the question text.

## Global Constraints

- **Rule 6:** no question or answer text on disk. The concepts file holds a short label (at most 40 characters, checked like a name), the goal's name, and a date. Question texts for the near-duplicate check live only in memory.
- **Never shown:** the concept stays on the server, like the answer.
- **Rule 5:** nothing here changes the map.
- **Set-asides:** a concept naming something set aside drops the question too (it goes through `fits`).
- **Tests:** two new tests in `test_race.py`; existing fakes gain `concept`. One eval case.

## Review Focus

1. **Claude omits or garbles `concept`:** the question is dropped, like any malformed one; a set with too few left still races if both tries together give 5.
2. **A day with many races:** 40 recent concepts in the prompt stay short (labels only), and the prompt never grows past them.
3. **A restart:** concepts survive (on disk); near-duplicate texts reset, which is fine.
4. **An educator and a student:** each player's concepts are their own file.
5. **A concepts file that's missing or broken:** treated as empty; a race never fails because of it.
