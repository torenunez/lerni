# v3.31: safe and separate

**Goal:** Fix what two outside reviews of v3.7–v3.29 confirmed: a worrying bonus answer is never lost, each student's grade uses their own set-asides, set-asides catch every English plural, student text can't break out of its fence, Chat pays only for answering a question, and the race never sticks after an error. Two of the admin's decisions ship with it: the bonus comes by chance only, and a doubted question set races only its agreed questions. "Delete for good" says what it keeps.

**Not in this version:** ids instead of names, notes revisions, safe file reads, level in results (v3.32); backups (v3.33).

## Changes

### 1. A worrying answer is never lost (`race.py`)

- `_grade(bonus, text, supervised, m)` returns `(tier, line, graded)`. `graded` is False when the grader is missing, raises, times out, or returns something unreadable.
- **Care counts either way:** `care: true` *or* `tier: "care"` is care.
- **Ungraded answers are kept:** `answer_bonus` writes the answer to the conversation log, tagged `{"bonus": "ungraded"}`, beside today's `{"bonus": "care"}`. So the admin sees an answer that couldn't be read (`lerni logs`).
- The student still gets "Points for trying!" and 2 ⭐: a service failure shouldn't cost them.

### 2. Each grade uses its own student's map (`race.py`)

- Remove `self._map_now`. `answer_bonus` reads the map and passes it into `_grade` as `m`.

### 3. Every plural (`interests.py`)

- One `forms(name) -> set[str]` returns a name, its plurals, and what it could be the plural of, using the last word of a multi-word name:
  - **"s" and "es":** as today (`ES_AFTER`, `NOT_PLURAL`, and never under 3 letters);
  - **y → ies** after a consonant: puppy, puppies;
  - **f / fe → ves:** wolf, wolves; knife, knives; leaf, leaves;
  - **irregulars:** child/children, mouse/mice, person/people, man/men, woman/women, tooth/teeth, foot/feet, goose/geese.
- `same_name` and `mentions_set_aside` use it. `_singulars` and `_plurals` become its internals.
- **The risk:** an extra candidate like "wolfe" is never a real name on the map, so matching errs toward blocking, as it does today.

### 4. One fence (`fence.py`, new)

- `fence(tag, text) -> str` returns `<tag>\n…\n</tag>`. Any opening or closing `tag` inside the text is removed, case-insensitive and with spaces allowed, repeating until none is left. So `</ans</answer>wer>` can't close the fence.
- **Used by:**
  - the bonus grader (`answer`);
  - the tagger, for the student's message and Lerni's previous message and answer (`student`, `lerni`);
  - Upload's notes (`notes`).
- Each system prompt already says this text is information, never instructions. The tagger's prompt names its tags.

### 5. Chat pays only for answering a question (`tagging.py`)

- An `answered` tag earns ⭐ only when Lerni's previous message contains "?". Otherwise the tag is ignored for points, and the map update goes ahead.

### 6. The race never sticks (`web/games.py`)

- `on_choice`, `on_bonus` and `on_next` get the same catch-all as `on_go`. On any error they redraw from the student's current race, or the start with "Something went wrong. Tap Race! 🏁". Never a stuck "Lerni is reading…".

### 7. The bonus comes by chance only (`race.py`)

- `_offer_bonus` offers the bonus only when the race drew it at the start (`lucky`, about 1 in 4). Being last no longer brings it. Coming last on purpose never pays more.
- In the docs, spec 09b's and the student PRD's "when behind" become "about 1 race in 4".

### 8. A doubted set races only what was agreed (`race.py`)

- `_verify` drops the "most disagree: keep them all" branch. It keeps the agreed questions, and `_write`'s second try writes more.
- If both tries still leave fewer than 5, the race isn't ready: "not ready" comes before the race is counted, so it costs nothing.
- **Checker down** (missing, error, wrong shape): the set races unchecked, as today, and the log says so.
- **The risk:** a checker that's wrong every time (say, off by one) would stop every race. Its log line, "Race check disagreed with N of M", makes that visible, and `eval_race` catches it before a deploy.
