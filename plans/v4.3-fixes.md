# v4.3: fixes (the v4.2 review, and the data fixes)

**Goal:**
- the race fixes in v4.2 do what they promise;
- an old suggestion, a restore, or a broken file can't undo the family's newer data.

**Why:**
- **The v4.2 review:** a fresh review found two real bugs after the merge.
- **Data:** the data fixes come from two outside reviews (the admin's order, [v4.1](v4.1-repeats-by-theme.md#decision-the-admin-2026-11-10)).

No screen changes, so there's no mockup.

## Race fixes (from the v4.2 review)

1. **Review ids:**
   - **The problem:** a review id is used up even when its question is then rejected (a wrong sum, set aside, a near-identical text). A later good question on that review loses the id, and the review stays due.
   - **The fix:** `_review` only finds the id. It counts as used once its question is kept.
2. **The same math written two ways is one idea:**
   - **The problem:** `normalize` now splits `−` and `-`, `×` and `*`, `6 / 2` and `6/2`, and `7-3` and `7 - 3`.
   - **The fix:**
     - **Signs:** `−` and `–` become `-`, `×` becomes `*`, and `÷` becomes `/`.
     - **Between numbers:** a sign stands apart, so `1/2` reads as `1 / 2` and `0-60` as `0 - 60`.
     - **A minus at the start, or after a space, `(`, `[`, or `=`,** is a sign, so `(-3)` and `x=-3` keep it.
   - **Unchanged:** a hyphen or slash inside words ("top-speed", "and/or") still reads as a space.
3. **Connections:** a goal's spread of interests counts the interest it actually used. Before, a connection took the slot while the spread counted the group that ranked first, so a goal with a connection could get the same interest on all 3 questions.
4. **Cars:** a set's car number is chosen only from numbers that at least 2 cars in reach have. With none, there's no comparison line.
5. **The eval:** the review case also checks that Claude returned `R1`, not only the label.

## Data fixes (from the outside reviews)

6. **An old goal suggestion can't overwrite newer notes (`morning.py`):**
   - **Recorded:** a goal suggestion stores the notes' key when it's made, as steps already do.
   - **On a tick:** if the goal's notes changed since, the tick is refused: "its notes changed since; tomorrow's plan can suggest again".
   - **The morning tidy:** drops a waiting suggestion whose notes changed.
   - **Older suggestions** have no key, so they're accepted as before.
7. **A restore keeps today's sign-in (`backup.py`):**
   - **For an account in both today's data and the copy:** the restored account keeps today's password and the higher of the two session versions.
   - **What this protects:** a password reset, or a device signed out since the backup, stays in effect. Devices signed in now stay signed in.
   - **Everything else comes from the copy:** maps, points, the account's other settings.
8. **A broken or unreadable file can't break Games or be overwritten (`points.py`, `concepts.py`, `jsonfiles.py`):**
   - **Points read safely:** they use `read_json`, so a broken file is moved aside (the admin can put it back) instead of raising on every Games action.
   - **Nothing unreadable is overwritten:** `read_json(strict=True)` raises when a file exists but can't be read (permissions), so the points and the concept ledger are never overwritten with an empty one.
   - **Writes survive a power cut:** they're flushed to disk (`fsync`) before the swap.

## Tests (minimal, fakes only; one regression per bug)

- **`test_fresher_races.py`:**
  - **review ids:** a rejected first question with `R1` doesn't take it from the good second one;
  - **math:** `−` and `-`, `6 / 2` and `6/2`, `7-3` and `7 - 3` match, and `(-3)` and `3` don't;
  - **connections:** a goal with a connection gets 3 different interests across seeds;
  - **cars:** with no car listing horsepower, horsepower is never the set's number.
- **`test_morning.py`:** a goal suggestion made before the notes changed is refused on a tick, and the notes stay.
- **The backup tests:** after a restore, a cookie signed out since the copy stays signed out, and today's password still works.
- **The points tests:** a broken points file is moved aside and Games reads 0 instead of failing; an unreadable one raises and isn't overwritten.
