# v3.33: stable ids

**Goal:** A goal's race history follows its id, not its name, so a rename keeps it. The same idea under two goals stays two. Questions written ahead never outlive a change to their goal's notes. A broken concepts file is moved aside, never overwritten. Each results line records the question's level and attempt, so the win rate can be decided from real results.

**Why:** the v3.7–v3.29 outside reviews (2026-10-27), confirmed then:
- a question finds its goal by name when it's answered, so a rename in between loses the link;
- the concept ledger is keyed by label alone, so "speed" under Cars and under Running is one idea;
- held questions keep racing after the educator rewrites a goal's notes;
- a broken concepts file reads as empty, and the next race overwrites it.

**Not in this version:** backups (v3.34); changing the win rate itself (decided after about two weeks of results).

## Changes

### 1. Questions carry their goal's id (`race.py`)

- `check_questions` and `check_bonus` find the goal once, when the question is checked (by name or alias, as today). `Question` and `Bonus` keep `goal_id` beside the goal's name.
- **Everything after uses the id:**
  - `fits`: the goal is still on the map as a goal;
  - `spread`: takes turns by goal id;
  - the results line, the goal's level, and its practice count.
- Nothing looks a goal up by name at answer time any more.

### 2. Ideas keyed by goal and label (`concepts.py`)

- Each ledger entry gains `goal_id`. An idea is the pair (goal id, label), so "speed" under two goals is two entries with their own counts and reviews.
- **The calls:**
  - `add(username, [(goal_id, goal, concept)])`;
  - `answered(username, goal_id, concept, right)`;
  - `due()` returns `(goal_id, goal, concept)`.
- `recent()` still returns labels only: it's what Claude hears.
- **Old entries** (no `goal_id`): the first `add` with the same label and the same goal name adopts the entry, keeping its counts. Until then, `due()` finds its goal by name, as today. No migration step; the file's schema becomes 4.

### 3. Questions written ahead follow the notes (`race.py`)

- Each question and bonus records `notes_key`, a short hash of its goal's notes when it was written.
- `fits` drops a held question whose goal's notes have changed since, as it drops a set-aside one. The bonuses held for later are filtered the same way.
- The next race writes fresh questions from the new notes.

### 4. A broken concepts file is moved aside (`jsonfiles.py`, `concepts.py`)

- `read_json(path) -> dict | None`:
  - a missing file gives None;
  - a broken file (not JSON, or not an object) is renamed `<name>.broken-<YYYYMMDD-HHMMSS>.json` beside it, with one log line naming it, and also gives None.
- The concepts store uses it: the race goes on with an empty ledger, and the next write starts a new file. The broken one is kept for the admin.
- **Unchanged:** a broken map, points, or account file already stops with an error and is never overwritten; the screen says something went wrong. The admin restores it from the nightly copies (`docs/reference/admin.md`).

### 5. Level and attempt in each results line (`race.py`, `concepts.py`)

- **`level`:** the goal's level (1–5) the question was written at.
- **`attempt`:** how many times this idea has been asked, this time included. 1 is new; 2 or more is a review or a repeat. `add` returns it.
- The bonus line gets both too. Older lines without them read as before.

### 6. Then the win rate (`docs/todo.md`)

A to-do item, not code. After about two weeks of results with levels, compare right answers by level, and places, against the target (about 60% right, 1 race in 3 won). Then decide whether to change the level steps (`UP_AT`, `DOWN_AT`) or the rivals' pace.
