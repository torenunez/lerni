# v4.6.1: questions written ahead survive a restart

**Goal:** a deploy or restart never leaves a student waiting for Claude at their next race.

## Why (the admin, 2026-11-12)

The student's race hung on production after the day's two deploys:

- **Held questions lived only in memory,** so each restart threw them away.
- **The start-up write-ahead had to start again,** and the student raced through what it wrote.
- **The next race waited on a live write,** and that write timed out after 150 seconds. Claude was slow that afternoon, and the shared account was near its limit.

This is the "kept on disk until the day ends" part of v4.9's overnight write-ahead ([longer sessions](longer-sessions.md); the admin approved the rule 6 addition there), pulled forward as a patch on `main`. v4.7 is rebased after it.

## The time limit (found 2026-11-12)

One real write for the student, timed on a copy of production's data, took 139 s against a 150 s limit (the code assumed about 70 s). Its prompt is 13,500 characters: the full map, the bank's examples, and v4.5's quality rules. About half the writes timed out, which is the `TimeoutError`s in production's log. `QUIZ_TIMEOUT_SECONDS` goes from 150 to 300; the writes run in the background, so the longer limit costs no one a wait. Why writes got twice as slow is on the to-do list.

## Code

- **`ahead.py` (new), `AheadStore`:** one file per student, `ahead/<user>.json`, holding the day, the unraced questions, and the bonus questions.
  - `save` replaces the file whole.
  - `load(today)` reads only today's files.
  - `purge(today)` deletes the files from earlier days.
- **`race.py`, `RaceDesk(ahead=...)`:**
  - **At start-up:** it deletes earlier days' files and loads today's back into the held sets.
  - **Saving:** `_persist` runs after every write, after a race takes its questions and its bonus, and when a bonus answer puts a question back.
  - **Best effort:** a failed save prints a line, and memory still holds the questions.
- **`web/app.py`:** wires the store, and the morning write-ahead deletes yesterday's files first.

**Unchanged:** questions held in memory still carry past midnight until the 5:00 write tops them up, which re-saves them under the new day. A restart between midnight and 5:00 loses them, and 5:00 refills.

## Tests (fakes only, minimal)

- **The happy path:** after a write-ahead and a restart, the next race starts with no new write, and the file loses the raced questions.
- **Rule 6:** an earlier day's file is never loaded, and it is deleted.

## Deploying

- **Safe while in use:** pull, reinstall, restart.
- **Mid-day deploys:** from this version on, a restart keeps today's questions.
- **This deploy's restart** still starts with none held, since nothing was saved before it. The start-up write-ahead refills, so give it about 2 minutes before the student races.
