# v4.2: race fixes (math identity, repeats per goal, review ids, fewer theme repeats)

**Goal:** races stop circling the same few themes, and the ideas behind them are counted correctly, before Version 4 builds its checked bank on them.

**Why:** these are the admin's calls in [v4.1](v4.1-repeats-by-theme.md#decision-the-admin-2026-11-10), from three reviews.

**The private repeat report:** the admin read it on their screen on 2026-11-10. It's a real student's data, so it isn't recorded here.

No screen changes, so there's no mockup.

## What changes

### 1. Math stays in labels and question hashes (`concepts.normalize`)

- **The problem today:** `normalize` keeps only word characters, so "1/2 + 1/4" and "1/2 − 1/4" both become `1 2 1 4`. "−3" also becomes `3`. They share one ledger idea, one vector in the meaning lookup, and one question hash.
- **The fix:** keep these as tokens:
  - numbers with their `.`, `/` and digit-grouping `,` (`0.5`, `1/2`, `1,000` becomes `1000`);
  - the operators `+ − × ÷ * = < > %`;
  - a `-` that is spaced or comes before a number, which covers subtraction and negatives.
- **Unchanged:**
  - a hyphen inside words or ranges ("top-speed", "0-60") still reads as a space;
  - case, punctuation and plurals behave as before.
- **No migration:** stored labels are normalized fresh on each comparison. Hashes of new questions change, which only matters for stats.

### 2. Repeats are checked within each goal (`check_questions`, `RaceDesk._write`)

- **The problem today:** every picked goal's "asked lately" list is pooled, so an idea asked on one goal blocks its first use on another (for example, "counting to four" on a music goal and on a counting goal).
- **The fix:** `check_questions` gains `by_goal`, the labels each goal mustn't repeat, keyed by the goal's lowercase name. A question is checked against:
  - its own goal's labels;
  - the labels with no goal, which apply to all goals;
  - labels kept earlier in this write.

  This applies to both the word check and the check by meaning.
- **Probes:** they keep checking against everything, since they have no goal.
- **Kept as is:** the near-identical question text check stays across the whole set.
- **Built from:** `_write` assembles `by_goal` from each goal's history and the held questions (by their goal), and adds each try's kept questions.

### 3. Each review has an id (`quiz_input`, `QUIZ_SCHEMA`, `check_questions`)

- **The problem today:** a review comes back under a new label ("sharing an odd count equally" for "halves of odd numbers"). It becomes a new idea, so the review never advances and stays due.
- **The fix:**
  - **The prompt** lists due ideas as `R1. idea (goal)`, and asks Claude to put that id in a new optional `review` field.
  - **The server** takes the due label exactly when the id exists, its goal matches the question's goal, and the id hasn't been used yet in this write.
  - **Otherwise:** the plural match (`_as_due`) still applies.

  An unrelated question can't advance a review just by returning an id.

### 4. Fewer theme repeats (`QUIZ_SYSTEM`, `roll`, `deal`)

- **The prompt:**
  - **dropped:** the example label "top speed vs acceleration";
  - **added:** "Every question also takes a different angle: never the same measurement, record, or comparison as another question in the set or a recent idea, in other words."
- **Quantity formats:** "closest guess", "a number from their interest" and "compare two things" go at most once per goal per set. `deal` swaps a goal's extra ones for the least-used format that isn't about quantity.
- **The "record" twist:** at most once per set (`roll`). Later draws pick another twist.
- **Interests per goal:** `deal` ranks a slot's interests by how often this goal already used each one in the set, then by the global count as today. A goal's 3 questions get 3 different interests when it has 3 to choose from. This also stops goals and interests falling into step.
- **Car comparisons:**
  - **One fact a set:** the server picks the number a set may compare (0-60 time, horsepower or price). It rotates per student in memory, never the same one twice in a row, and the prompt names it.
  - **Counted across tries:** a comparison kept in the first try counts in the second (`check_questions` gains `compared`).

## Tests (minimal, fakes only; one regression per bug)

- **`test_fresher_races.py`:**
  - **math identity:** the two labels normalize differently and hash differently, and the ledger keeps 2 ideas;
  - **repeats per goal:** through `_write` with a fake quizzer, a label asked on goal A is kept on goal B, and is still dropped on A;
  - **review ids:** a reworded review with `R1` on the right goal takes the due label; the same id on another goal doesn't;
  - **the deal:** across seeds, a goal's slots never repeat an interest when 3 groups exist, and each set has at most one quantity format per goal and one "record" twist;
  - **the car count across tries:** with `compared=1`, a second two-car question goes to spare.
- **The eval** (`scripts/eval_race.py`): one case where a due idea comes back with its `R` id. Real Claude, run by hand.
