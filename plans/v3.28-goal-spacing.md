# v3.28 Goal spacing and subject areas: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every goal comes back on a spaced schedule, and each goal has a subject area, so progress can be read by area.

**Why:** Claude picks which goals each set of race questions covers, and it favours a few. Production, the week to 2026-10-24:
- 23 goals;
- one got 15 questions and another 14;
- 5 got one each;
- 5 got none, all added on 2026-10-22.

Only single ideas have a schedule today (v3.22's missed-idea review).

**The admin's decisions (2026-10-24):**
- spaced repetition for goals, per [learning concepts](../docs/learning-concepts.md): boxes per goal;
- subject areas on goals, in the same version:
  - Lerni proposes an area; a person's tap sets it (rule 5);
  - the card and the races use areas;
- the card is renamed "Goal progress this week" and sorted by how much each goal was practiced;
- the order (updated the same day): the fast race start first (v3.27), then this, read-aloud questions (v3.29), One Chat (v3.30), and probes (v3.31).

**Architecture:**
- **Goal boxes (`concepts.py`):** each goal's entry in the levels ledger gains `box` (0–3) and `due` (ISO), next to `level`.
  - Box gaps are `GOAL_DAYS = (1, 3, 7, 14)` days.
  - `ConceptStore.raced(username, per_goal, today)` runs once per finished race, for each goal it asked, from that race's right/asked on the goal:
    - all right: up one box;
    - half or fewer right: back to box 0;
    - otherwise: the same box.

    `due = today + GOAL_DAYS[box]`.
  - `ConceptStore.schedule(username)`: `{goal_id: (due, box)}`.
  - A goal that was never raced has no entry, so it's due now.
- **Picking a set's goals (`race.py`):** `pick_goals(m, schedule, asked14, today, k=5)`.
  - Due goals come first: the most overdue first, then the fewest questions in the last 14 days (from the results log).
  - They're interleaved by area: one from each area in turn, so a set mixes subjects.
  - With fewer than 5 due, it fills from the soonest due.
  - Due single ideas (v3.22) still come back on their own. Their goals are added to the set if they're missing.
- **The prompt:**
  - `quiz_input(…, goals=…)` lists only the picked goals.
  - `QUIZ_SYSTEM` asks for 2 questions per listed goal.
  - A goal that's hard to ask as multiple choice (feelings, values) gets one question, and a bonus if one fits.
  - `check_questions` still accepts any goal on the map, so held questions stay valid.
- **Subject areas (`interests.py`):**
  - `Entry` gains `area: str = ""` (goals only), checked like a name (`check_name`).
  - Old maps load with no area; the journal diffs whole entries, so it needs no change.
  - Removing a goal keeps its area in `removed_info`, and Put back restores it.
- **The starter areas in code** are generic: Math, Science, Language, Music, Feelings, Thinking. Any other area lives only on the map file, on the home server, never in the repo (rule 8). Lerni sees the areas already on the map plus the starters, and may propose a new short one.
- **Lerni proposes areas (`educator_agent.py`):**
  - A goal proposal gains `area`: one already on the map or a starter, or a new one only when none fits. Its label shows it, "🎯 Spanish numbers 11 to 20 · Language", and flags a new one, "· new area: World languages". An area exists only once a goal with it is added.
  - A new proposal kind, `area` ("📚 Fractions → Math"), sets an existing goal's area.
  - The agent's map text shows each goal's area, or "(no area)".
  - New rule: when asked to sort the goals, propose an area for each goal without one.
  - **Backfill:** the educator types "sort the goals into areas" in the Suggest box, ticks, and taps Add once. No new screen.
- **The card (`web/games.py`, `results.py`):** "Goal progress this week".
  - Rows are grouped under each area's heading with its total ("Math · 22 of 30").
  - Areas are sorted by questions asked, most first; goals inside each by questions asked, most first.
  - Goals with no area go under "Other", last.
  - `ResultsLog.week` returns `goal_id` too, so the area comes from the map; a renamed goal keeps its rows.
- **The list (`web/mentallist.py`):** inside the Goals section, a small heading per area ("Math (6)") with its goals under it. Areas come in the card's order, with Other last; a map with no areas stays flat, as today. This holds on both screens. An open goal's facts line gains "Area: Math", read-only. Changes go through the Suggest box.

## Global Constraints

- **Rule 5:** an area is set only by a person's tap on a proposal. Spacing changes which goals are asked, never the goals themselves.
- **Rule 6:** the ledger and the map hold labels, ids, dates and numbers only.
- **Rule 8:** only generic starter areas in code, tests, and docs; the family's own areas stay on the home server.
- **Tests (rule 4):**
  1. `test_race.py`, `test_each_set_goes_to_due_goals_mixed_by_area`:
     - a never-raced goal is picked before one due next week;
     - all right moves a goal to 3 days;
     - a miss brings it back tomorrow;
     - the prompt lists only the picked goals;
     - two goals in the same area aren't both picked while another area waits.
  2. `test_web_roles.py`:
     - an area proposal changes the goal only when ticked;
     - Put back keeps the area;
     - the card groups by area, sorted by questions asked;
     - the goals list puts goals under their area's heading.
- **Eval:** `eval_educator.py` gains "sort the goals into areas", which proposes an area for every goal without one. Run by hand once.

## Review Focus

1. **A map with no goals:** races ask about how their interests work, as today, with no goal lines and nothing picked.
2. **A goal renamed or removed** between races: the schedule is keyed by id; a removed goal's entry is ignored.
3. **Fewer than 5 goals:** all of them, every set.
4. **Held questions written before a goal moved boxes** still race. Spacing shapes new sets only.
5. **The first deploy:** every goal already raced has no box yet, so it's due now. Box 0 starts at the next race, so nothing is starved.
