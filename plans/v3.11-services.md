# v3.11 Services that say when they fail: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `lerni service` never says "Started." or "Restarted." for a server that isn't answering. It passes Lerni's settings to the server, and refuses or warns about the setups that would quietly go wrong.

**Architecture (`src/lerni/student/service.py`, `src/lerni/commands/service.py`):**
- **Settings reach the server.** `install` copies every `LERNI_*` variable from the shell into the agent: `LERNI_SAY_VOICE`, the models, and `LERNI_WHISPER_MODEL`.
  - `LERNI_STUDENT_DATA` is the exception: it comes only from `--data` or dev's default. So a shell pointed at development's data can never point production there.
- **The data check compares real folders.**
  - It compares with `os.path.samefile` when both folders exist, or with resolved, lowercased paths otherwise. So different case and symlinks count as the same folder.
  - It refuses:
    - development on production's data;
    - production on development's data;
    - development on port 7860, and production on 7861.
- **Warnings at install** (printed in yellow; the install still goes ahead):
  - `claude` or `whisper-cli` isn't on the PATH being saved, for example when installing over SSH;
  - production's checkout holds a commit that isn't on `origin/main` (`git merge-base --is-ancestor HEAD origin/main`).
- **Waiting for the server.** After `install` or `restart`, the command waits up to 30 seconds for `status` to say "running".
  - If it never does, the command prints the last 10 log lines and exits with an error.
- **A crash loop slows down:** `ThrottleInterval` goes from 10 to 30 seconds.
- **Logs rotate.**
  - **When:** on `restart`, a log over 5 MB moves to `<name>.log.1`, replacing an older one.
  - **Why it works:** launchd opens the log again when it starts the new process.
  - `install` still starts a fresh log.
- **Plainer messages:**
  - `stop` says "Wasn't running." when nothing was loaded;
  - `status` says "stopped" for an agent that's installed but not loaded;
  - `restart` after `stop` starts it again from its agent file, instead of saying "isn't installed";
  - a hand-edited, unreadable agent file says "install it again" instead of showing a traceback;
  - `launchctl` errors print once.

**Tech Stack:** Python 3.11+ standard library (`shutil.which`, `os.path.samefile`), typer, pytest with a fake `launchctl` (existing `Launchctl` in `tests/test_service.py`).

**Spec:** the [admin reference: Running on its own](../docs/reference/admin.md#running-on-its-own); v3.6 review items in the to-do; the ML review's N2–N4.

## Global Constraints

- **No real `launchctl`, `git`, or network in tests:** fakes are passed in, as today.
- **Nothing private in the agent files' code:** paths come from the machine at install time.
- **Production never runs a branch** (CLAUDE.md rule 10). A warning, not a refusal, because the production checkout's branch is `production`, which follows `origin/main`.
- **Tests:** one test for the settings and refusals (a safety guarantee), and one for "says when it fails". Existing tests keep passing.

## Review Focus

1. **A server that takes 20+ seconds to start** (a Gradio cold start on a busy Mac): 30 seconds is enough, and the command never claims success early.
2. **A shell with `LERNI_STUDENT_DATA` set** when installing production: it's ignored.
3. **Log rotation while launchd still writes:** the old process writes to `.1` until it's killed. Nothing is lost, and nothing crashes.
4. **`restart` when the agent file is missing:** it still says "install it first".
5. **`status` with no agent loaded and nothing on the port:** it says "stopped", never a traceback.
