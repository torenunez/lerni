# v3.27 The race starts fast: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tapping Race! starts a race at once nearly every time, and when it must wait, the screen says why instead of showing "processing" on every car.

**Why (2026-10-24):**
- **The student waited over a minute** after tapping Race!, with every garage car showing "processing".
- **Measured on the real map:**
  - writing one set of questions (10 questions, 2 bonus) took 60 seconds;
  - the blind check took 3 seconds;
  - a set with fewer than 5 good questions takes a second call, about 2 minutes in all.
- **Questions are written ahead** when Games opens and after each race. That doesn't help:
  - after a restart (the held questions live in memory; production restarted twice that day);
  - at the first race of a new day (held questions are dropped at midnight);
  - when Race! is tapped right after opening Games.
- **The "processing" on every car** is Gradio's loading overlay on every output of the Race! event, garage tiles included.

**The admin's decisions (2026-10-24):** this first; then goal spacing and areas (v3.28, its plan on `feat/v3.27-goal-spacing`), read-aloud questions (v3.29: a 🔊 button and an auto switch), One Chat (v3.30), and probes (v3.31).

**Architecture:**
- **Questions kept across days (`race.py`):**
  - `_held` no longer drops a set at midnight, and neither does `_bonuses`.
  - A held question is still checked against today's map at the start (`fits`: set-asides, goals still there).
  - Due reviews and levels shape new sets only, as today.
- **Writing ahead earlier:**
  - **At sign-in (`web/main.py`, the load handler):** for a player (a supervised student or an educator), `desk.prefill(...)`. It runs in the background and returns at once, and it does nothing when a race's worth is already held or no race is left today.
  - **At server start (`web/app.py`):** `desk.prefill(username, supervised=True)` for each active supervised student, so a restart doesn't cost the next race a minute.
- **The wait, said plainly (`web/games.py`):**
  - Race! first sets the note to "Lerni is writing your questions… ⏳" (a quick step that skips the queue), then starts the race.
  - The overlay shows only on the note and the Race! button (`show_progress_on`), never on the garage.
  - A race that starts at once replaces the note straight away.
- **The box says what it does (`web/educator.py`):** the heading becomes "Suggest or change a goal", and the placeholder "New goal, or 'easier notes for Fractions'…". The box already handles new notes, removals, groups, and feedback; only renaming stays in the list.
- **The student picker after a restart (`web/educator.py`):** a page left open across a restart sent its old pick and logged an error ("not in the list of choices"). The picker accepts any value (`allow_custom_value=True`); every handler already checks the student with `map_owner` on the server.

**Tech Stack:** Python 3.11+, Gradio 6.30, pytest.

**Spec:** [spec 09](specs/09-play-and-points.md) (the race; "written ahead" updated).

## Global Constraints

- **Rule 6:** held questions stay in memory only, as today.
- **Rules 5 and 9:** unchanged; phone-size check of the waiting note.
- **Cost:** no more Claude calls than today. Sign-in and startup write only when fewer than a race's worth is held. Keeping questions across days saves calls.
- **Tests (rule 4):** one regression test in `test_race.py`, `test_held_questions_last_past_midnight`:
  - a set written on day 1 starts a race on day 2 with no second call to the quizzer;
  - a question whose goal was removed overnight isn't used.

## Review Focus

1. **The sign-in write and the Games-open write at once:** one call, not two (`_busy` already guards this; check that it does).
2. **A day with no races left:** no write at sign-in.
3. **The note** never stays "writing…" after a race starts, or after an error ("The track needs a minute").
4. **Startup** with no Claude set up, or no supervised students: nothing happens, and nothing breaks.
5. **A forged student value** in the picker is still refused by `map_owner`.
