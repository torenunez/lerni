# v4.5: bulk labels and the checked bank

**Goal:** the admin rates a batch of race questions per goal in a Google Sheet, and Lerni writes better questions from those ratings.

**Why:**
- **The admin found questions that don't make sense:** a dealt format was forced onto a goal it doesn't fit.
- **Rating in bulk is faster than in the app.**

**There's no model training.** The ratings steer Claude through the prompt:
- **Good questions** become examples Claude sees for their goal.
- **Bad and needs-a-fix questions,** with their reasons, become lines to avoid, and that exact question never races.

**Banked questions don't race yet.** That comes with checking a few questions (the daily sample).

## The admin's calls (2026-11-11)

- **The sheet** goes in the admin's Google account. So the student's goals and interests, which appear in the question text, leave the home server for it.
- **The columns:** Rating (a dropdown) and Notes come right after Goal; there's no Problem column, since Claude infers the problem from the notes when it reads the sheet back (the admin's call, 2026-11-11).
- **The v4.3 review fixes came first** (v4.4).

## The sheet (the mockup)

The rows below are made up.

| Adding to 10 | Bad | An odd one out doesn't fit adding | Which is the odd one out: +, =, or 5? | + | = | 5 | C | 5 is a number | dinosaurs | odd one out | 9c1d… |

- **Rating:** Good / Needs a fix / Bad.
- **Notes (optional, free text):** when Claude reads the sheet back, it infers the problem from them: wrong answer, confusing, format doesn't fit, too easy, too hard, off the goal, or same as another.
- **Layout:**
  - rows sorted by goal;
  - the header row frozen;
  - Rating's dropdown set by data validation;
  - the narrow `id` column holds the question's fingerprint (`results.question_hash`).

## The workflow (Claude runs it in a session when the admin asks)

1. **Write a batch:** `lerni race batch --user U [--data DIR] [--per-goal 8] --out FILE`.
   - **Data:** copies the data folder to a temp folder, so the real data is never written; the copy is deleted at the end.
   - **The desk:** built as the server builds it, with the same quizzer and embedder as `serve.py` and the blind check.
   - **The goals:** taken 3 at a time, each chunk written with `RaceDesk._write(..., goals=chunk)`. Each round's kept questions are held, so the next round avoids them. Rounds repeat until every goal has `--per-goal` questions, at most 4 rounds.
   - **The output:** only questions that pass every check, probes included under the goal "Nearby ideas". The file is written 0600, in Claude's scratchpad.
   - **Printed:** numbers only.
2. **Make the sheet:** Claude creates it through the Google Sheets connector, after loading the `google-workspace` skill, then deletes the batch file.
3. **The admin rates the rows,** on any device.
4. **Read the sheet back:** Claude reads it into a temp JSON (0600) and runs `lerni race labels FILE --user U [--data DIR]`, which writes the bank and prints numbers. Claude then deletes the temp file and offers to delete the sheet; the admin confirms.

**Cost:**
- **Claude calls:** about `ceil(goals / 3) × rounds` writes on the small model, each with a blind check.
- **Example:** 15 goals at 8 each is about 5 × 4 = 20 writes.
- **Before a run,** Claude says the count first.

## Code

### `RaceDesk._write(..., goals=None)` (`race.py`)

- **Given goals:** they replace `pick_goals`, and due ideas are kept only for those goals.
- **Not given:** unchanged for races.

### `src/lerni/student/batch.py` (new)

- **`write_batch(root, username, quizzer, *, supervised, today, per_goal, checker, embedder) -> list[dict]`:** builds its own desk on the copy;
  - the rounds and chunks above;
  - rows hold the sheet's columns, plus `goal_id`, `concept` and `probe`;
  - rows are sorted by goal.

### `src/lerni/student/bank.py` (new): `BankStore`

- **Where:** `bank/<user>.json`, through `read_json(strict=True)` and `write_json_atomic`.
- **Each item:**
  - `id`, `goal_id`, `goal`, `question`, `choices`, `answer`, `why`;
  - `concept`, `format`, `setting`;
  - `rating`, `problem`, `notes`;
  - `day`, and `by: "educator"`.
- **The API:**
  - **`add_labels(user, rows, map, today) -> (kept, skipped)`:** rows keyed by the sheet's headers (any case) or `choices`/`answer`; an `id` that isn't a 12-character fingerprint is recomputed;
    - **Kept:** only rated rows.
    - **Matching a row to its goal:** by `goal_id`, falling back to the goal's name (`race.goal_of`).
    - **Skipped:** a row whose goal is gone. Probes have no goal, so they're skipped too.
    - **Relabelling:** a new rating replaces the item with the same id.
  - **`good(user, goal_id, k=2)`:** the newest Good items on that goal.
  - **`wrong(user, goal_id, k=3)`:** the newest Bad or Needs-a-fix items on that goal, each with its problem or notes.
  - **`blocked(user) -> set[str]`:** the ids of every Bad or Needs-a-fix item.

### Steering the race (`race.py`)

- **`quiz_input(..., marked=None)`:** two sections after the goals, leaving out any row touching something set aside:
  - **"marked good:"** its good questions, each with its right answer and any note;
  - **"marked wrong:"** its wrong ones, each with its problem or notes.
- **`QUIZ_SYSTEM`** adds: "Write new questions as good as the ones marked good, never copies; avoid the mistakes in the ones marked wrong."
- **`check_questions(..., blocked=())`:** drops a question whose fingerprint is blocked.
- **`RaceDesk(bank=...)`:** wired in `web/app.py`. `_write` passes the bank to both.
- **A broken bank file** never stops a race: it's moved aside and races go on as before.

### The CLI (`src/lerni/commands/race.py`, new)

- **The group:** `race_app`, with the commands `batch` and `labels`, added in `cli.py`.

### Question quality from the ratings (added 2026-11-11, the admin's call)

From the admin's notes on the test round, in `QUIZ_SYSTEM`:
- numbers realistic for the setting (a soccer score isn't 37), or something else counted;
- choices that are plain answers, not explanations or methods (a rival's mistake excepted);
- a hard word or part (a clock's long and short hands) explained in the question first;
- no sentence the question doesn't need, and no label in front ("Mystery:");
- each question uses only its planned interest (settings are already dealt evenly; the test map had only 3 interests, so dinosaurs were about a third, and broad variety notes wait for Tell Lerni);
- short sentences and everyday words.

The "a bit of history" twist is gone (`TWISTS`): even with the rule, it came out as a "Long ago, …" sentence tacked on.

Checked with `scripts/eval_race.py quality` (one call): on the old prompt it failed plain choices, explained hands, and tacked-on sentences; on the new one all pass. Then a real batch on a copy of production's data, one goal first (its questions were too hard and off the goal), rated by the admin before merge.
